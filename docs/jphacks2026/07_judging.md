## 審査方法（概要）

JPHACKSは、予選に位置づけられる **Hack Day** 及び決勝戦に位置づけられる **Award Day** の2つのステージから構成されています。

| 賞 | 審査する人 | 審査方法 | 審査対象 | その他 |
| --- | --- | --- | --- | --- |
| [Hack Day]<br>Hack Day Audience Award | **参加者（一人1票）**、提携校などの先生方・スポンサー・審査員（**一人3票**） | 1票1点<br>各ブロック1位が表彰 | プレゼン | 同点の場合は決選投票＋おかわりプレゼン |
| [Hack Day]<br>Award Day Finalist | 審査員 | 審査観点の通り<br>上位15チーム程度 | git、プレゼン（録画）、動画 | |
| [Award Day]<br>Best Audience Award | **参加者全員（一人1票）** | 1票1点<br>全体1位が表彰 | プレゼン | |
| [Award Day]<br>Best Hack Award | 組織委員、審査員 | 審査観点の通り<br>最上位チームが表彰 | プレゼン、展示会 | |

### [最重要] Award Day進出への道

- Award Day へ進出するためには、下記の審査基準にのっとり、審査員が厳正に審査します
- その**点数の上位15チームが Award Day Finalist として表彰**されます（Hack Day 終了後、審査におおむね1週間程度かかります）
- **各拠点から必ず1チーム**は選ばれます
- **デモが動いていることが最重要視されます。プレゼンでデモが実際に動くことを証明してください**

### Hack Day の表彰

- Hack Day では、参加者の投票で Best Hack Day Award が授与されます
- 票数が同点の場合は、1分30秒の追加プレゼンと決選投票が行われます
- 投票は「このチームに Award Day に行ってほしい」と思ったチームに入れてください
- 不正な投票を行ったとみなされたチームは失格になることがあります

### Award Day の表彰

- **Best Hack Award（優勝）**
  - 予選同様の審査基準＋（プレゼンテーション力）で、組織委員及び審査員が点数をつけ、最も高い得点を獲得したチームを表彰
  - 2位以下のチームから審査員特別賞が表彰されることがあります
- **Best Audience Award**
  - 参加者全員が参加する投票で最も多くの票を集めたチームを表彰
  - 不正な投票を行ったとみなされたチームは失格になることがあります

## 審査基準

以下の4項目を審査基準とします。4. プレゼンテーション力は Award Day のみの審査基準です。

1. 問題着眼点・着想点
2. 実行・実現可能性
3. 完成度・動作性
4. プレゼンテーション力（Award Day のみ）

## 各審査基準の得点と採点ポイント（各基準5点）

### 1. 問題着眼点・着想点

問題着眼点もしくは着想点が優れているかを判定する。

- **着眼点**：解いている問題が明確で新しいこと
- **着想点**：既知の未解決の問題に対して、解き方が新しいこと

| 点 | 採点基準 |
| --- | --- |
| 5 | 問題着眼点が全く新しい、着想点が斬新で課題が解決された |
| 4 | 問題着眼点・着想点が新しい、着想点が斬新で課題の一部が解決された |
| 3 | 問題着眼点・着想点が明確である |
| 2 | 問題着眼点・着想点が一部不明瞭 |
| 1 | 問題着眼点・着想点が不明瞭 |

### 2. 実行・実現可能性

実際に世の中で利用される可能性が高いサービス／サービスのスケーラビリティが高い。

| 点 | 採点基準 |
| --- | --- |
| 5 | 投資すれば多くの想定ユーザに使ってもらえるサービスになりえる、このままサービスになる、競合に対する優位性がある |
| 4 | 投資すれば多くの想定ユーザに使ってもらえるサービスになりえる、競合に対する優位性がある |
| 3 | 想定ユーザに使ってもらえるサービスであり、熱意がある |
| 2 | 想定ユーザに使ってもらえるサービスであるが、競合との差異があまり感じられない |
| 1 | 想定ユーザが不明確である |

### 3. 完成度・動作性

実装されたプロダクトによって、コンセプトで提示された課題が解決しているか？

| 点 | 採点基準 |
| --- | --- |
| 5 | コンセプトで提示された課題が解決しており、プロダクトにわくわくする |
| 4 | コンセプトで提示された課題が解決している |
| 3 | コンセプトで提示された課題がほぼ解決している |
| 2 | コンセプトで提示された課題の一部が解決している |
| 1 | コンセプトで提示された課題が解決されているか不明瞭。ミスマッチに見える |

### 4. プレゼンテーション力（Award Day のみ）

問題点、解決方法、動作デモができているか？理解できたか？

| 点 | 採点基準 |
| --- | --- |
| 5 | 問題点、解決方法、デモが適切な時間で説明され、会場の聴衆を引き付け感動をさそった |
| 4 | 問題点、解決方法、デモが適切な時間で説明され、会場の聴衆を引き付ける要素があった |
| 3 | 問題点、解決方法、デモが適切な時間で説明された |
| 2 | デモが適切な時間で説明されたが、問題点、解決方法が分かりにくかった |
| 1 | 内容が伝わらなかった。説明が時間内に終わらなかった |

## 制約事項

- **事前開発は可能。ただし、事前に作った部分をメインの着眼点にするのは不可。** また、評価項目3は、あくまで Hack Day の期間中での実装のみを評価対象とする
- 技術の準備も OK。ただし、審査基準はあくまで問題解決に焦点が当たるため、使用した技術は評価対象外。開発の中で作った技術は大きく評価
- 技術自身をハッカソン内で開発した場合はそれを評価する

## 審査方法（詳細）

### Hack Day のオーディエンス投票

- Hack Day の中でオーディエンス投票を実施（各参加学生1票＋審査委員・スポンサー・共催などのゲスト3票）
- 自分のチームには投票できない（その他、不正な投票が発覚したチームは失格になることがあります）
- 審査基準に則り、Award Day に行くべきと思ったチームに投票する（スポンサー、共催の先生は複数票を1チームに入れることも可能）
- Hack Day で実装した内容を評価し、動作している内容で評価する

### Hack Day 後のオンライン審査（Award Day 進出の選抜）

- Hack Day の提出物を元に、審査委員会にてオンライン審査を実施
- 上記の審査基準を元に、上位約15チームを決定
- 各会場最低1チームに Award Day への出場権が与えられる

### Award Day

- オーディエンス投票を実施（審査委員会＋組織委員会＋オーディエンス）
- 発表者は自分のチームには投票不可
- オーディエンス投票の集計により、最も票が多かったチームを Best Audience Award として表彰
- 審査委員が評価項目をもとに採点を実施
  - ある一定以上の評価を得たチームを Innovator 認定として表彰
  - 最も点数が高かったチームを Best Hack Award として選出
- その他に優れていると判断されたチームを審査委員特別賞として選出（任意）
